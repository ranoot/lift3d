# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`lift3d` is a CUDA/C++ project for 2D↔3D lifting. The core module implements the
**point-to-pixel mapping from SGS-3D** (arXiv:2509.05144v2): it projects a world-space
point cloud into a camera image, reconstructs visibility from the cloud itself with a
z-buffer (no depth sensor needed), and emits a per-point correspondence map.

## Build & run

```bash
# nvcc must be on PATH (see gotcha below)
export PATH=/usr/local/cuda/bin:$PATH
cmake -S . -B build        # ~6 min: PCL/VTK detection dominates configure time
cmake --build build -j
./build/demo_mapping       # point-to-pixel demo (needs a working GPU)
./build/pcd_write_test     # PCL starter, writes test_pcd.pcd
```

Override the GPU target when you know the card: `-DCMAKE_CUDA_ARCHITECTURES=86`.
There is no test framework wired up yet; `demo_mapping` is the smoke test.

## Gotchas (read before debugging)

- **The GPU does not run here.** This is WSL2 with a broken GPU passthrough:
  `nvidia-smi` fails (`Failed to initialize NVML`) and CUDA programs fail at runtime
  with *"CUDA driver version is insufficient for CUDA runtime version"*. `nvcc`
  **compiles** fine; kernels just can't execute until the *Windows-host* NVIDIA driver
  and `wsl --update` are refreshed. Verify CUDA changes by compiling, not running.
  **Never install a Linux NVIDIA driver inside WSL** — it breaks passthrough further.
- **`nvcc` is not on PATH by default.** The toolkit lives at `/usr/local/cuda` but the
  installer doesn't export its `bin/`. `~/.bashrc` sets `CUDA_HOME`/`PATH`/`LD_LIBRARY_PATH`;
  new shells are fine, otherwise prepend `/usr/local/cuda/bin` manually.
- **PCL pulls in VTK, which needs the `C` language enabled.** The CMake project must
  declare `LANGUAGES C CXX CUDA` — without `C`, VTK 9.5 fails configure on a missing
  `MPI::MPI_C` target. Keep `C` in the `project()` line.
- **clangd needs `.clangd` (already in repo).** Two traps it papers over: (a) `gcc-16`
  is installed but its libstdc++ headers are not (`/usr/include/c++/16` missing), so
  clang auto-picks GCC 16 and every `std::` symbol vanishes — pinned with
  `--gcc-install-dir=…/15`; (b) CUDA 13 moved libcu++ into `include/cccl/`, so
  `<cuda/atomic>` needs that extra `-I`. The nvcc flags in `compile_commands.json`
  (`--options-file`, `--generate-code`, …) are stripped there too. Validate without the
  editor via `clangd --check=point_pixel_mapping.cu` (the `tweak: DefineInline` lines it
  reports are not real errors).
- **`compile_commands.json` is a symlink to `build/`** — regenerated by CMake. If clangd
  reports `Root directory: nil`, the symlink is stale/broken; re-point it at
  `build/compile_commands.json`.
- **Configure is slow (~6 min)** because of PCL's dependency probing. Reuse the `build/`
  dir for incremental rebuilds; only `rm -rf build` when changing project-level settings.

## Architecture

The CUDA mapping is intentionally **PCL-free** so any front end can reuse it; PCL is
only linked into the `pcd_write_test` starter.

- `point_pixel_mapping.cuh` — public API: `Camera` struct (row-major `K` 3×3, `T` 4×4
  camera-to-world **rigid** pose, image `W`/`H`) and `projectPointsToPixels(...)`, which
  returns the visible-point count or `-1` on CUDA error.
- `point_pixel_mapping.cu` — host wrapper + two kernels:
  1. `projectKernel`: applies the precomputed 3×4 matrix `M = K · (T⁻¹)[0:3,:]`
     (rigid inverse `[Rᵀ | −Rᵀt]` built host-side in `buildProjection`), writes per-point
     `(u,v)` and depth, and atomically z-buffers the nearest depth.
  2. `visibilityKernel`: marks a point visible iff in-frame and
     `|zᵢ − D(u,v)| ≤ τ_vis`, filling the `[u,v,1]` correspondence map.
- `demo_mapping.cpp` — synthetic two-quad occlusion scene exercising the full path.

### Conventions that matter

- **Pose convention:** `T` is treated as camera-to-world and inverted internally. If a
  caller supplies world-to-camera poses, the inverse must be skipped — check before reuse.
- **Z-buffer atomics use modern libcu++**, not the legacy `atomicMin`/`atomicCAS`
  intrinsics: `cuda::atomic_ref<int>::fetch_min` plus `cuda::std::bit_cast` (requires
  C++20, which the build sets). The float→int reinterpret is deliberate — IEEE-754 bit
  patterns are monotonic for positive depths, enabling a portable *integral* `fetch_min`.
- Pixel index is computed **once** in `projectKernel` and reused by `visibilityKernel`
  (read back from `out_uv`) so both stages agree on rounding.
